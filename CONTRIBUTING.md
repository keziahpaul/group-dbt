### :beetle: Reporting Bugs

If you encounter any bugs, please create a new JIRA ticket or issue on GitHub. Provide detailed information about the problem, including steps to reproduce, expected behavior, and actual behavior.


### :bulb: Suggesting Enhancements

All feature requests are welcome! Describe your proposed changes in detail, and explain the motivation behind them.

While we will consider all requests, we cannot guarantee your request will be accepted. We want to avoid feature creep. Your idea may be great, but also out-of-scope for the project. If accepted, we cannot make any commitments regarding the timeline for implementation and release. However, you are welcome to submit a pull request to help!

### :ok: Submitting Pull Requests

**Before opening your PR**

- Ensure branch naming convention is followed

- Submit one pull request per feature or bug

- Smaller chunked pull request are preferred over one large one

- For bigger and complex changes please coordinate and discuss a strategy with codeowners

- When writing commit messages, explain the why not the how and what


**Before submitting your PR**

- Ensure pull request description is filled out according to template

- Follow existing coding style and conventions

- Inlcude test coverage

- Do not refactor code that is unrelated to your change

- Resolve any merge conflicts that occur

- Address any CI failures

**Post your PR being merged**

_if applicable_

- Add documentation

- Update changelog
